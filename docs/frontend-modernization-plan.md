## 3. 目标与优先级

### P0：正确、可用、安全

1. 用量入口不再跳转到 404，刷新和分享链接保留筛选。
2. 网络错误、业务失败、会话过期、无权限分别呈现，并提供可执行反馈。
3. 普通用户只能看到本人统计；管理员与超级管理员能力按当前后端授权区分。
4. 0、null、缺字段和异常缓存数据不混淆；不出现 NaN、undefined 或虚构统计。
5. 令牌、渠道密钥默认隐藏；删除、禁用和批量清理均有明确确认。

### P1：统一、现代、易读

1. 参考 SHUAI API 的固定顶栏、深色底、细边框、低装饰和清晰层级，改造成适合管理台的数据密集型布局。
2. 统一排版、间距、低圆角容器、表格、表单和状态标签。
3. Dashboard 先呈现结论，再解释趋势与缓存数据可信度。
4. 表格筛选、分页、操作和表单反馈形成一致交互。

### P2：增强项，单独确认后实施

- 统一用量明细 API、明细抽屉和 CSV 导出。
- 普通用户模型排行、令牌排行，以及全局搜索。
- 复杂快捷键、自动刷新和额外主题。

P2 不作为本轮交付前提，不得用假数据或抓取全部日志来替代缺失接口。

## 4. 信息架构与路由

### 4.1 导航分组

| 分组 | 页面 | 可见角色 |
| --- | --- | --- |
| 概览 | Dashboard / 用量分析 | 已登录用户；普通用户限定本人 |
| 使用 | 模型广场、令牌、日志、可选聊天入口 | 已登录用户 |
| 管理 | 渠道、用户 | 管理员及以上 |
| 配置 | 个人设置 | 已登录用户 |
| 配置 | 系统、运行、其他设置 | 按现有 root 授权 |
| 公共 | 首页、关于、登录、注册、重置密码 | 无需登录，遵守注册开关 |

不增加后端没有的数据面板：不凭空展示实时吞吐、费用、首 Token 延迟、协议支持徽标或缓存节省金额。

### 4.2 路由策略

- 保留现有 `/dashboard`、`/channel`、`/user`、`/token`、`/log`、`/plaza`、`/setting` 和编辑路由，避免破坏收藏链接。
- 建议新增 `/usage` 用量分析页，复用已有聚合 API。
- 将 `/console/usage` 设为兼容别名，带查询参数重定向到 `/usage`；同步修复 UsersTable 链接。
- Dashboard 是默认概览，Usage 是筛选与排行工作区，两者共享组件和请求服务，不复制两套统计逻辑。
- URL 保存 `user_id`、`token_id`、`channel_id`、`model_name`、时间范围；筛选变化重置分页。
- `user_id` 是管理员筛选参数，普通用户不得通过 URL 切换他人范围。
- 登录后返回原目标页；无权限页返回可访问页面，不把所有权限错误重定向成登录失败。
- 页面标题、导航高亮和面包屑由统一路由元数据产生；编辑页归属父级导航。

## 5. 视觉设计规范

方向：参考 [SHUAI API](https://api.shuaiapi.com/) 的“开发者 API 门户”风格，但不复制其品牌、文案或页面结构。核心特征是深色画布、固定透明顶栏、近乎无阴影的细边框、白色主标题/灰色辅助文字、低圆角甚至直角按钮、窄而明确的操作层级，以及“公开信息 + 可核对数据 + 清晰边界”的表达方式。One API 控制台仍需优先保障统计可读性、表格密度和权限操作。

参考页面观察记录（2026-10-09）：默认深色背景约为 `#1C1C1C`，正文使用白/灰层级，字体接近 Public Sans；顶栏约 64 px 且固定，导航不使用厚重底色；操作按钮以白底深字的主按钮和透明/细边框次按钮区分；内容模块主要使用分隔线、留白和轻微半透明边框，不依赖重阴影。以上是风格方向，不是要求逐像素复制。

### 5.1 设计变量（初始候选值）

| 项目 | 规范 |
| --- | --- |
| 页面背景 | `#1C1C1C`；控制台局部层级可用 `#232323` / `#2A2A2A` |
| 卡片背景 | 默认透明或 `rgba(255,255,255,.035)`，不使用大面积白卡片 |
| 主文字 / 次文字 | `#F5F5F5` / `#AFAFAF` |

| 成功 / 警告 / 错误 | `#63D391` / `#F2C66D` / `#FF8585`；必须同时配文字或图标 |
| 间距 | 4、8、12、16、24、32 px |

候选颜色需通过实际组合的对比度测试，不因写入本计划即视为无障碍合格。

### 5.2 样式边界

- 在控制台根节点设置 CSS 变量和命名空间，不覆盖公共 Markdown/iframe 的样式；默认主题为深色。
- Semantic UI 继续提供成熟控件，公共包装组件统一外观和行为。
- Dashboard.css 仅保留图表/该页特有样式；共享卡片与 Tab 样式移至公共层。
- 避免新增无命名空间的 `.ui.card`、`.ui.header` 全局覆盖；已有覆盖分阶段移除。
- 字体优先采用现有系统字体栈；若引入 Public Sans，必须评估内网离线部署，不得让字体网络请求成为页面依赖。
- 保留主题切换扩展点，但浅色主题不是本轮主要验收目标；主题切换不能改变数据语义和状态颜色。

## 7. 页面改造规格

### 7.1 Dashboard：一眼理解使用情况

从上到下：

1. 页标题、当前范围、筛选摘要、最近成功更新时间和刷新。
2. 总/输入/输出 Token、请求次数四项概览。
3. Token 缓存命中率、调用命中率、覆盖率三项；另显示读取/写入 Token。
4. 数据质量提示：未上报数量、异常数量；展开说明指标口径。
5. Token 趋势：输入、输出、缓存读取分系列展示；缓存读取是输入的一部分，不做额外相加。
6. 管理员模型、用户、渠道排行；普通用户只有当前已有授权的数据视图。

先完成 7/30/90 天和全部范围的一致行为；自定义时间范围作为 P1 后续项。刷新时保留上一次成功数据并显示“更新中”，失败时标记旧数据时间，不能让旧数据看似当前范围的新数据。

图表不使用双轴制造不可比较的趋势。请求数与 Token 可用独立图表/切换指标。图例允许切换系列，Tooltip 提供精确值。没有样本与明确为零的数据分开处理，不对缺失日期默认补零，除非后端契约明确其含义。

### 7.2 Usage：可追溯的聚合分析

- 管理员支持用户、令牌 ID、模型、渠道和时间过滤；普通用户走 self 接口。
- 汇总、趋势和排行必须使用同一筛选快照，不混用不同时间范围。
- 管理员点击用户/模型/渠道排行可设置筛选；“清除全部”恢复默认。
- 第一期是聚合分析页，不宣称提供每请求明细。
- 普通用户没有 self 排行接口时隐藏排行区，不调用管理员接口碰运气。

### 7.3 令牌管理

- 列：名称、状态、创建/到期时间、权限摘要、操作；新用量列仅在可靠来源确认后启用。
- Key 默认遮盖，复制不等于永久展示；明确显示/隐藏操作，不自动保存明文到浏览器存储。
- 删除不可恢复、禁用影响调用，确认框显示令牌名称和影响。
- 创建成功给出一次明确的 Key 获取提示；复制失败应有手动获取路径。
- 保留模型限制、网段限制和有效期，不恢复额度输入。

### 7.4 渠道管理

- 主表突出名称、类型、状态、模型、分组、优先级和已提供的测试结果。
- 长模型列表折叠；编辑、测试、禁用分层排列，危险动作不与主操作同权重。
- 新建/编辑按基础信息、连接配置、模型与权限、高级参数分区。
- 密钥保持原值与更新行为明确；JSON 配置错误定位到字段，不只弹全局 Toast。
- 批量测试/删除禁用渠道显示影响范围和执行状态；没有后端进度接口时不伪造百分比。

### 7.5 用户管理

- 用户名、邮箱、角色、状态、分组、历史请求数/新统计入口的语义清楚。
- 历史 `users.request_count` 如继续显示，明确标为历史计数，不标为当前时间范围调用数。
- 新用量入口进入 Usage 并保留 user_id，禁止逐行请求 summary 形成 N+1 请求。
- 编辑、禁用、删除、角色调整遵守现有权限，并提示影响。

### 7.6 日志

- 保留已有日志查询；突出时间、用户/令牌、模型、渠道、输入/输出 Token、流式标识和请求 ID。
- 历史日志与新 usage 统计说明分开；日志总 Token 不直接冒充 Dashboard 的新口径总量。
- request_id 支持复制；长内容按需展开，不一次渲染完整大文本。
- 现有日志没有缓存明细时，不补零、不伪造“未命中”；每请求缓存状态需等待明细 API。
- 时间、类型、模型、渠道筛选和分页状态尽量写入 URL，回到列表保留上下文。

### 7.7 模型广场

- 搜索、可用模型数量、当前分组、复制模型名形成清晰首屏。
- 桌面默认紧凑列表，移动端可用卡片；展开渠道保留当前授权范围。
- 不显示成本、倍率；不根据模型名猜测支持图片、工具或原生 Responses。
- 接入示例可作为静态帮助内容，但协议能力必须以已验证范围为准。

### 7.8 设置与鉴权页

- 设置页区分个人、运行、系统；保留当前 root 权限边界。
- 表单分组、字段说明、未保存提示、提交状态和局部成功反馈统一。
- 首轮继续沿用现有单项 option 更新协议，不伪装成原子“保存全部”；多项保存失败要显示已成功/未成功项。
- 登录、注册、重置密码使用独立窄栏布局，验证码倒计时、字段校验、失败重试一致。
- 保留邮箱验证码与注册开关，不引入新登录方式；不在重构中破坏自定义首页、公告和聊天链接。

## 8. 数据契约与依赖

### 8.1 已核实可用接口

| 角色/用途 | 当前接口 |
| --- | --- |
| 管理员汇总与趋势 | `GET /api/usage/summary`、`GET /api/usage/trend` |
| 管理员排行 | `GET /api/usage/by-user`、`GET /api/usage/by-model`、`GET /api/usage/by-channel` |
| 普通用户统计 | `GET /api/usage/self/summary`、`GET /api/usage/self/trend` |
| 管理员筛选 | user_id、token_id、channel_id、model_name、start_timestamp、end_timestamp |
| 普通用户筛选 | self 固定本人；支持的其余参数按当前后端契约使用 |

截至本次核查，router/api.go 没有注册 `/api/usage/by-token` 或 self 排行接口；实施记录出现相关说法不能替代实际路由验证。不能依赖未注册接口作为第一期前提。

summary 已有 Token 总量、缓存读取/写入、三率，以及 generated_calls、error_calls、not_reported_cache_calls、invalid_cache_calls。缺少的可信数据包括 usage 来源占比、请求级缓存明细、统一统计时区和可供前端读取的 cutover 元数据；这些是后端增量依赖，不由前端推导。

### 8.2 指标展示规则

- 三率直接读取后端聚合结果，不对排行或每日百分比求平均。
- `null` 展示“—”和不可计算原因；明确 0 展示 `0%`，二者不能合并。
- 缓存写入不是命中，缓存读取已包含在归一化输入 Token 中。
- 命中率分母是后端认定的可计算样本输入量，不是全部输入量。
- `invalid_cache_calls > 0` 显示数据质量警告；不把异常率裁剪到 100%。
- 上游 Prompt Caching 与网关 Redis 缓存明确区分。
- 不从旧 quota 字段、费用兼容接口或用户历史计数反推 Token。
- 不把缺字段显示为 0；没有 usage 来源占比时不显示“100% 真实上报”。
- 当前后端日期桶使用数据库方言表达式，不能假定均为 Asia/Shanghai；前后端必须约定时区，再开放自定义日期范围。

### 8.3 请求状态治理

- 统一 API 模块保留 `{success,message,data}` 检查；HTTP 200 + success=false 仍为业务失败。
- Axios 拦截器必须继续拒绝错误；Toast 与页面错误约定单一通知 owner，避免双重弹窗。
- 筛选变化取消旧请求或使用请求序号阻止过期结果覆盖；并发各区块处理局部失败。
- 会话验证完成前显示初始化状态，不能仅凭 localStorage 展示可信管理员界面。
- 表单重复提交禁用，失败保留输入，禁止在请求日志中记录密码或 Key。
- 不引入新状态管理库；先抽取小型请求 hook 和 service，避免过度封装。

## 9. 响应式与无障碍

| 宽度 | 行为 |
| --- | --- |
| ≥1280 px | 常驻侧栏；指标四列，排行可两列 |
| 768–1279 px | 侧栏可折叠；指标两列；表格容器滚动 |
| <768 px | 抽屉导航；图表单列；筛选分行；操作不依赖 hover |
| 390 px 测试点 | 页面无整体横向溢出，允许明确标识的表格区域横向滚动 |

- 键盘可操作导航、下拉、表单和弹窗；可见 focus，不用颜色单独传达状态。
- 抽屉/弹窗支持 Esc、焦点约束与关闭后焦点返回。
- 图标按钮有可读名称；字段标签绑定输入框；表单错误可被辅助技术读取。
- 关键触控目标约 44×44 px，图表提供同等数据表或摘要。
- 对正文文字按 4.5:1 对比度目标验收；动画尊重 prefers-reduced-motion。
- 恢复滚动条，不通过隐藏滚动反馈营造整洁。
